What this system does

You define credits and debits (a paycheck, the rent, a subscription), each with an amount, optional start and end dates and a recurrence pattern. The API expands them into dated occurrences and adds them to your initial amount, producing a day-by-day forecast you can read as a chart, a ledger or an Excel workbook. Debt Paydown shows how quickly a debt is paid off when you send part of your income to it.

Security

  • JWT bearer tokens (15 minutes) with single-use refresh tokens, rotated on every refresh
  • Passwords hashed with BCrypt; the guest login happens on the server
  • Roles drive both the API ([Authorize(Roles = …)]) and the UI (admin guard and menu); each user only reaches their own items, forecast and debts
  • One response envelope for every success and error, with a correlation ID for each failure

How a forecast is built

Each item stores only the recurrence fields its time period needs. Fpfl.Display has one expander per pattern that turns those fields into dated occurrences inside the requested range; LedgerBuilder then adds them to the initial amount, one row per day with a running balance. It's pure business logic with unit tests, replacing the original version's stored procedure.

Debt Paydown

Pick a debit you're paying down, enter what's owed, as of which date, and an optional APR, then send a percentage of any credits to it. PaydownCalculator reuses the expanders: the debit's own payment and each allocated share reduce the balance, interest (APR ÷ 12) is added at each month end, and it looks up to 30 years ahead for the payoff date. Allocations also appear in the main forecast as "Debt Paydown" debits, and no credit can be allocated more than 100% across all debts.
